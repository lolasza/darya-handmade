# Подключение DARYA HANDMADE к Vercel

## Что подготовлено

Ветка `review/published-html-sync` отправлена в GitHub. В ней все 21 товар и изображения опубликованного эталона. Разрешение пользователя на подключение и публикацию получено в чате; повторное подтверждение этих действий не требуется.

`vercel.json` задаёт статический сайт: Framework Other, без установки и сборки, Output Directory `.`. Корень проекта — корень репозитория. `.vercelignore` исключает служебные отчёты и Git-метаданные; все изображения остаются в публикации. `.vercel/` исключена из Git, чтобы локальные настройки и загруженные переменные не попали в коммиты.

Vercel CLI 64.7.0 установлен в текущей облачной среде:

```text
/workspace/shared/darya-vercel-cli/node_modules/.bin/vercel
```

Для CLI используются доступные для записи каталоги:

```sh
export XDG_CACHE_HOME=/tmp/darya-vercel-cache
export XDG_DATA_HOME=/workspace/shared/darya-vercel-state
export NODE_USE_ENV_PROXY=1
export NODE_USE_SYSTEM_CA=1
export VERCEL_TELEMETRY_DISABLED=1
export NO_UPDATE_NOTIFIER=1
```

Для команд передавайте `--global-config /workspace/shared/darya-vercel-state`. Не отключайте проверку TLS или проверку целостности пакетов. Секреты и файлы авторизации не добавляйте в Git.

## Что ещё требуется

В момент подготовки конфигурации сетевой шлюз среды возвращал `403 Forbidden` для `api.vercel.com`, `vercel.com`, `darya-handmade.vercel.app` и `api.github.com`. HTTPS Git-транспорт при этом работает: отправка review-ветки подтверждена.

Существующие переменные, настройки и локальные каталоги авторизации проверены: `VERCEL_TOKEN` отсутствует, Vercel CLI сообщает `Logged out`. Обычное разрешение на работу с проектом не создаёт авторизацию стороннего аккаунта автоматически.

В черновик настроек облачной среды добавлены необходимые сетевые адреса и требование `VERCEL_TOKEN` для `api.vercel.com`. Токен вводится только в защищённом поле настроек среды. Значение нельзя присылать в чат, записывать в этот файл или коммитить. У токена должен быть доступ к аккаунту/команде, владеющей существующим проектом.

Сохранение черновика не применяет эти настройки к работающей машине. После сохранения и применения настроек нужно заново проверить реальные запросы. Пока доступ и авторизация не появились, связь с существующим проектом и production-деплой не подтверждены.

## Продолжение после применения доступа

1. Проверить наличие `VERCEL_TOKEN` без вывода значения, затем выполнить read-only запрос `api.vercel.com/v2/user` с авторизацией через поддерживаемый прокси.
2. Найти существующий проект и команду, владеющие `darya-handmade.vercel.app`. Проверить проект, домен и текущую Git-связь. Не создавать дубликат и не переносить чужой домен по предположению.
3. Связать локальный checkout с найденным проектом через `vercel link --yes --project <verified-project> --scope <verified-scope>` и проверить `.vercel/project.json` без вывода секретов.
4. Подключить `https://github.com/lolasza/darya-handmade` через `vercel git connect`. Если у Vercel GitHub App нет доступа к репозиторию, пользователь должен предоставить его в настройках интеграции. Не подменять это произвольным токеном другого сервиса.
5. Проверить production branch, Root Directory и настройки статического деплоя. Подготовленная версия сейчас в review-ветке; не считать старый `main` новой версией. Запустить production-деплой именно готовой версии, дождаться состояния Ready и назначения нужного домена.
6. Проверить по публичному адресу HTTP 200, 21 товар, изображения, RU/EN, мобильное меню, корзину, подготовленную Telegram-ссылку на `Daria_Alexsandrowna` и отсутствие ошибок JavaScript. Сообщения в Telegram для проверки не отправлять.

Команды авторизации и публикации должны использовать существующее безопасное связывание токена, например `--token "$VERCEL_TOKEN"`, без shell tracing и вывода значения. Идентификаторы проекта и команды нужно получать из Vercel, а не придумывать.
